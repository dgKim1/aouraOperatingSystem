# 개발 기록 (devlog)

> 소유: 개발 기록 담당 `aoura-recorder` (정의 `~/.claude/agents/aoura-recorder.md`). 다른 역할은 이 폴더를 고치지 않는다.
> 목적: 심사자 · 새 개발자가 "무엇을 · 왜 이렇게 만들었는지"를 시간순으로 따라갈 수 있게 한다. 기준 문서(`docs/` · `CLAUDE.md`)가 이 기록과 다르면 기준 문서가 우선이다.

## 1. 파일

| 파일 | 내용 |

## 2. 기록 규칙

### 2-1. 작업 기록 (LOG)
```
### LOG-0NN · HH:MM · 백엔드|프론트엔드 · <한 줄 제목>
- 무엇을: 만든 · 바꾼 파일과 기능 (경로)
- 왜: 설계 의도 — 어떤 요구 · 규칙 · 수용 기준을 만족시키려고 (문서 · 규칙 ID 링크)
- 대안과 선택 이유: 검토했거나 버린 방법 (있을 때)
- 검증: 테스트 · npm run check 결과 (숫자 그대로), 골든 값 대조
- 가정 · 미해결: 새 가정, 문서와 다른 점, 다음 단계로 넘긴 것
- 출처: 에이전트 보고 | git diff | 문서 — 보고에 없는 의도는 (추정) 표시
```
- `LOG` 번호는 날짜 파일을 넘어 **전체에서 이어진다**(다음 날 파일도 마지막 번호 + 1).
- 작업 도중 찍은 기록은 제목에 `[진행 중]` 을 붙인다. 완료 보고가 오면 **앞 항목을 고치지 않고** 새 LOG 를 쓰고 "LOG-0xx 이어서"라고 연결한다.
- 시각은 KST, 보고를 받았거나 작업 트리를 확인한 시각.

### 2-2. 설계 결정 (DD)
```
## DD-0NN <결정 제목>
- 날짜 · 영역 · 상태(채택 | 대체됨 → DD-xxx)
- 맥락 / 결정 / 이유(근거 문서 · 규칙 ID · 원본 근거) / 버린 대안 / 영향(코드 위치 · 테스트 · 화면)
```
- 구조 · 타입 · 계산 방식 · 상태 전이 · API 계약 · 화면 구성 · 라이브러리 선택처럼 나중에 "왜 이렇게 했지?"를 물을 만한 것만 올린다.
- 결정이 바뀌면 새 DD 를 만들고, 이전 DD 의 상태를 `대체됨 → DD-xxx` 로만 바꾼다(본문은 남긴다).

### 2-3. 원칙
- 보고에 없는 의도를 사실처럼 쓰지 않는다 → **(추정)**. 코드 주석에서 읽은 의도는 "주석 근거".
- 숫자 · 테스트 결과는 보고나 실행 출력에 나온 값만 쓴다.
- 출처 라벨(`원본` · `집계` · `원본근거해석` · `가정` · `주장` · `모의`)을 기록에서도 유지한다.
- 비밀값 · `.env*` 내용은 기록하지 않는다. 대화체 · 내부 메시지 ID 는 넣지 않는다.
- 코드 · 다른 문서에 문제가 보이면 고치지 않고 LOG 의 "가정 · 미해결"과 보고에 **확인 필요**로 남긴다.
- 커밋하지 않는다(커밋은 메인 세션 · 사용자 판단).

## 3. 갱신 절차 (메인 세션 → 기록 담당)

메인 세션은 백엔드 · 프론트엔드 에이전트가 보고하거나 알림을 보낼 때마다 기록 담당을 불러 다음을 넘긴다.

1. **넘길 것**: 에이전트 보고 원문(만든 것 · 의도 · 버린 대안 · `npm run check` 결과 숫자), 메인 세션이나 사용자가 새로 정한 결정(날짜 포함).
2. **기록 담당이 하는 일**:
   1. 이 README 와 `DESIGN_DECISIONS.md`, 최신 날짜 파일을 읽고 마지막 `LOG` · `DD` 번호를 확인한다.
   2. `git status` · `git diff` · 새 파일 목록으로 마지막 기록 이후 변경분을 확인한다(`node_modules` · `.env*` 는 보지 않는다).
   3. 보고와 변경분이 다르면 둘 다 적고 **확인 필요**로 표시한다. 필요하면 `app/` 에서 `npm run check` 를 실행해 결과를 숫자 그대로 적는다(파일은 고치지 않는다).
   4. 오늘 날짜 파일(`YYYY-MM-DD.md`)에 LOG 를 추가한다. 없으면 새로 만든다.
   5. 설계 결정이 있으면 DD 를 추가 · 대체 표시한다.
   6. 아래 목차를 갱신한다.
   7. 추가한 LOG · DD 번호와 제목, 확인 필요 항목을 짧게 보고한다.
3. **`[진행 중]` 항목 정리**: 해당 역할의 완료 보고가 오면 새 LOG 로 결과를 적고, 스냅숏의 (추정)이 맞았는지 · 틀렸는지 표시한다.
