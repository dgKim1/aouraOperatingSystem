### 0-4. 시연 운영 주의 (2026-11-14)

- **서버 상태는 하나다**(DB `sim_state` 1행, DD-039). 프리셋 재생 · 시점 이동 · 회신은 접속한 모든 사람에게 같은 상태로 보인다. 두 사람이 동시에 시연하면 서로의 조작이 섞인다 — 다른 사람이 시점을 옮기면 내 화면의 기한이 지나 있고, 다른 사람이 리셋하면 내가 만든 승인요청이 사라진다.
- **시연은 한 사람만 조작한다.** 심사자 · 관람자는 조회만 하도록 안내한다(역할 전환은 각자 브라우저 쿠키라 섞이지 않지만, 쓰기는 공용 상태를 바꾼다).
- **시작 전에 리셋한다**: S-13 [전체 초기화] 또는 시작할 시나리오의 [초기화 후 재생]. 리셋은 운영 테이블만 비우고 원본 적재 테이블은 그대로다. 시연 도중 상태가 꼬이면 해당 프리셋으로 다시 재생해 이어간다(재생은 같은 결과 — 1절).
- **판단안을 만드는 동안 다른 쓰기를 하지 않는다.** 그 사이 상태가 바뀌면 409 `CONFLICT`("다시 만드세요")로 거부된다(낙관적 잠금 — ONTOLOGY 1-3 Assessment). 모의 모드는 즉시 끝나 거의 일어나지 않는다.
- **역할 전환은 시연 장치다.** 승인 회신은 서버가 `requiredRole` 을 검사하고(R-AUTH-05), 작업 처리 · 보충 초안도 서버가 담당 역할(작업 `ownerRole` · SCM)을 검사한다(A-35, BE-17 구현됨 — 화면에서는 S-06 · S-07 [권한 검증 확인]으로 422 를 보인다). 사람의 신원 확인(로그인)은 없다 — 제출 설명에 적는다(ONTOLOGY 1-3 쓰기 행위별 허용 역할).
- **AI 모드는 모의로 시연한다**(`AOURA_AI_MODE=mock`, ONTOLOGY 9-1). 헤더 · 판단안의 `모의` 표시를 가리지 않는다.
- **권장 순서**: ① → ② → ③(A · B) → ④. 각 시나리오는 해당 프리셋 재생으로 시작하면 앞 시나리오의 조작 결과에 기대지 않는다. 단계별 역할 · 버튼 · 소요 시간은 [0-6 시연 진행표](#0-6-시연-진행표-한-장-2026-11-14).
- **개발 서버로 시연할 때**: 프리셋 정의를 바꾼 뒤에는 dev 서버를 다시 시작해야 반영된다(LOG-023). `next build` 는 dev 서버가 도는 폴더가 아닌 별도 사본에서 한다(새로고침 반복 현상 — 원인 미확인, LOG-022 · 023).

### 0-5. 확장 · 부서 영향 정의
- **E1 (나만의 확장) 통보 수령확인 상태** — R-EXT-01. 원본 공백 "실제 통보 수령 증빙이 없다"(W02 5절)를 상태로 관리. 없으면: 발송만으로 "통보 완료"가 되어 기한 감시가 자동 갱신을 막았다고 판단 / 있으면: 수령 미확인 시 재통보 작업 · `NOTICE_UNCONFIRMED` 에스컬레이션으로 **처리가 달라진다**.

- **D1 재무(covenant)** — R-AUTH-03. 재무팀의 제약(30억 하회 구간 신규 현금 약정 제한)이 마케팅 기안의 **승인 주체**를 바꾼다.
- **D2 SCM · Corevia** — 리드타임 · MOQ · 기발주 입고 시점이 캠페인 **집행 계획**을 바꾸고, 보충 발주는 다시 covenant 경로를 탄다.
