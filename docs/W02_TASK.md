## 1. 핵심 질문

> 실적 보고, 캠페인 확대 기안, 연간 계약의 갱신 통보가 따로 움직일 때 **무엇을 먼저 연결해야 하는가?**

한 줄 해석: 같은 날(2026-07-17) 마감되는 **① 캠페인 확대 기안**과 **② INF-001 전속계약 갱신 통보**는 권한도 결정도 별개인데, 기안만 심사하고 전속계약을 방치하면 **미통보 자동 갱신(= 승인 권한을 거치지 않은 연 28억 체결)** 이 일어난다.

- 확대안 승인 기준은 **예상 GMV가 아니라 실질 공헌이익**. 기안의 예상 GMV는 쿠폰·반품·광고비·물류비 차감 전.
- 확대안 계약 확정기한이 지나면 **자동 확정 · 철회 불가** → 미결정으로 기한을 넘기면 **묵시적 승인**.
- **Agent 는 권한 경계를 넘는 결정을 자동 확정하지 않고 사람에게 상신한다.**

### 3-4. 실질 공헌이익 — 공식 정의와 계산 재료 [원본]

**공식 정의** — `00_common/calculation_definitions.md` 1.4 「캠페인 실질 ROAS」 (채점 대상, **정의 그대로** 적용):

```
Nominal ROAS = Attributed GMV / Marketing Spend
Real ROAS    = Contribution Profit / Marketing Spend

Contribution Profit = Net Revenue − COGS − Coupon Discount − Influencer Fee − Paid Media Spend
                      − Channel Fee − Fulfillment Cost − Return Refund − Return Logistics Cost
```

- Net Revenue = GMV − 반품환불액 (GMV 는 쿠폰 반영 후 · VAT 제외)
- **Marketing Spend = `mkt_ad_spend_ms.ad_cost_krw` 전액** (media = 인플루언서 + 퍼포먼스 + 오프라인)
- COGS · Channel Fee · 물류비 = `mkt_cost_master_ms` 고정값 · 캠페인 귀속 = **last-click 7일**
- ⚠ **해석 주의**: 정의상 Net Revenue 에서 이미 반품환불을 뺐는데 산식에서 Return Refund 를 다시 빼고, "쿠폰 반영 후" GMV 에서 Coupon Discount 를 다시 뺀다. 공식값은 **정의 그대로** 계산하되, 이중 차감 여부를 설계 설명에 **명시**한다(필요하면 비교용 대안 값을 [가정] 으로 함께 표시).
- 참고: 회의록(재무팀)의 산식 "GMV − 쿠폰 − 반품환불 − 광고비 − 인플루언서 비용 − 채널 수수료 − 배송/반품물류비" 는 **[주장]** 이며 COGS 가 빠져 있다 → 공식 정의를 우선한다.
- 관련 지표: 반품률 = Σ반품환불액 / ΣGMV (**금액 기준**, 벤치마크 8%) · 재구매율 = 90일 내 재구매 고객 / 최초구매 고객 (벤치마크 22%) — `calculation_definitions` 1.6 · 1.7

| 재료 | 파일 | 연결 키 |
|---|---|---|
| GMV · 쿠폰할인 | `02_masil/marketing/mkt_orders_ms.csv` | `campaign_id`, `sku_id`, `channel_id` |
| 쿠폰 사용(중복 여부) | `02_masil/marketing/mkt_coupons_ms.csv` | `order_id` |
| 반품 환불 | `02_masil/marketing/mkt_returns_ms.csv` | `order_id` |
| 광고비 · 인플루언서 비용 | `02_masil/marketing/mkt_ad_spend_ms.csv` | `campaign_id` |
| 원가 · 채널수수료 · 배송/반품물류비 | `02_masil/marketing/mkt_cost_master_ms.csv` | `sku_id` × `channel_id` |
| 캠페인 → 인플루언서 | `02_masil/master/m_campaign_ms.csv` | `campaign_id` → `influencer_id` |
| 인플루언서 정보 | `02_masil/master/m_influencer_ms.csv` | `influencer_id` |

- 커머스 계열은 **대표 표본** → 결론은 **비중 · 순위 · 방향**까지만. 연간 계획치(인플루언서 65억 등)나 28억에 표본 비율을 곱하지 않는다(`data_dictionary` 6항, 회의록).
- 재무팀 메모: INF-001 의 **기존 실질 공헌이익은 지금까지 산출된 적이 없다.**

### 3-5. 재무(자금) 연결 — [원본] `covenant_terms_ms.md`, `calculation_definitions.md` 1.2

- covenant: `closing_balance` 가 **30억**을 영업일 하루라도 하회하면 위반.
- 재전망으로 **하회 예상 구간**에 현금이 나가는 신규 약정(캠페인 계약 포함)은 금액 불문 **그룹 CEO 승인**.
- 기안은 자금 전망 유출 산식에 **포함되지 않으므로** "마케팅 축소 = 자금 해법"으로 제시하지 않는다. 시점 대조의 목적은 **승인 주체와 순서**다.
- `fin_cash_forecast_ms.csv` 는 재무팀 **공식 전망 = 주장**. 스케줄(AR·AP(`po_id='NONE'`)·발주)로 재시뮬레이션해 대조해야 한다.

### 3-6. 캠페인 → 재고 · 공급 연결 — [원본] `02_masil/inventory/`, `02_masil/master/m_sku_ms.csv`

| 재료 | 파일 | 내용 |
|---|---|---|
| SKU 마스터 | `master/m_sku_ms.csv` | `source_company`(**Corevia** 등), 안전재고 주수 min/max, **MOQ**, **리드타임(주)** |
| 현재고 | `inventory/sku_inventory_ms.csv` | `on_hand_qty`, `in_transit_qty` (2026-06-30 스냅샷) |
| 주간 판매 | `inventory/sku_weekly_sales_ms.csv` | `week`, `sku_id`, `sold_qty` |
| 재고 발주 | `inventory/sc_purchase_orders_ms.csv` | 공급사(Corevia), 발주량 · MOQ · 리드타임 · 대금 · 지급일 |
| 캠페인 → SKU | `marketing/mkt_orders_ms.csv` | 주문 행에 `campaign_id` × `sku_id` |

재고 커버 공식 — `calculation_definitions` 1.3:
```
Available Qty    = on_hand_qty (본 데이터룸에는 reserved_qty 없음)
Weeks of Supply  = available_qty / 최근 4주 평균 주간 판매
Suggested Order  = max(Target Qty − available_qty − in_transit_qty, 0) → MOQ 반영
```
- 커버 계산의 현재고는 `on_hand_qty` 만 (`in_transit_qty` 미합산).
- 재고 · 발주 · 자금 계열은 **풀스케일**, 커머스 주문 계열은 **표본** → 캠페인 수요 상승분을 재고 수량에 그대로 더하지 않고 **비율 · 방향**으로만 연결하거나, 연결 방법을 **[가정]** 으로 명시한다.
- 예: SKU-1001 은 Corevia 공급 · MOQ 24,000 · 리드타임 **12주** → 7/17 결정으로 늘어날 판매는 **현재고 + 기발주 + 12주 뒤 입고**로만 감당 가능. 판매계획 변경은 Corevia(생산·조달)에 전달할 정보가 된다.
- 발주 대금(`sc_purchase_orders_ms.payment_due_date`)은 Masil 현금 시뮬레이션의 유출 항목 → covenant 판정과 연결된다.

### 3-7. 추가 시나리오 — 캠페인의 성공을 회사의 실행계획으로 바꿀 수 있을까? (추가 전달 사항)

> Masil에서는 인플루언서 캠페인 직후 주문이 늘었지만 일부 상품의 **품절, 긴급배송, 고객 문의와 반품**도 발생했습니다. 마케팅은 캠페인 성과를, 물류와 CS는 추가 부담을 각자 보고했습니다. 회사가 실제로 무엇을 얻었는지 함께 설명하는 일은 쉽지 않았습니다.
>
> 다음 **캠페인 확대안과 전속계약 갱신**도 검토해야 합니다. 어느 **파트너 · 상품 · 채널**을 선택할지뿐 아니라 **언제까지 결정**해야 하며, **어떤 상품을 얼마나 공급할 수 있는지** 확인해야 합니다. 판매계획이 바뀌면 **재고 보충과 생산 · 조달**에는 어떤 정보가 전달되어야 할까요?

이 시나리오가 W02 에 더하는 요구:

| 요구 | 시스템에서의 의미 | 데이터 |
|---|---|---|
| 회사가 실제로 얻은 것 | 마케팅 성과(GMV) · 물류 · CS 부담을 **한 화면에서** 실질 공헌이익으로 합친다 | 3-4 |
| 파트너 · 상품 · 채널 선택 | 인플루언서 × SKU × 채널 단위로 실질 성과 비교 | `mkt_orders_ms`, `mkt_cost_master_ms`, `m_campaign_ms` |
| 언제까지 결정 | 기안 확정기한 · 전속계약 통보기한 · covenant 하회 구간을 **하나의 타임라인**에 | 3-1, 3-3, 3-5 |
| 얼마나 공급 가능 | 승인하려는 캠페인의 주력 SKU 재고 커버 · 입고 일정 · 리드타임 확인 → 부족하면 **조건부 승인 / 일정 조정** | 3-6 |
| 생산 · 조달로 전달 | 판매계획 변경 → **재고 보충 요청(발주 제안)** 생성 → Corevia 로 전달할 정보(SKU · 수량 · 필요 시점 · MOQ) | 3-6 |

- 물류 추가비용 · CS 문의는 회의록상 **별도 집계되어 원본 파일이 없다** → 쓰려면 **[가정]** 데이터로 만들어 표시한다.
- 이 시나리오는 "다른 부서 영향"(SCM · 물류 · CS · Corevia 생산)의 가장 자연스러운 후보다.

## 5. 미해결 지점 (원본에 없음)

- 계약 원문, **성과 피 정산조건**, **실제 통보 수령 증빙**이 없다.
- 연간 계약과 캠페인별 비용의 **귀속 · 중복 여부**를 대사할 자료가 없다.
- 담당자별 **검토 · 상신 · 결정 · 통보 이력**이 없어 실제 지연 원인을 확정할 수 없다.
- 법무·계약 담당의 독립 부서 존재와 서명 절차는 확정되지 않았다.

→ 시스템에서 이 부분을 쓰려면 **[가정] 데이터로 새로 만들고 화면에 가정 표시**해야 한다(원본 수정 금지).

## 6. 확장 질문 (W02 안내)

1. 갱신과 개별 집행 중 **어떤 결정의 누락**을 문제로 정의할 것인가?
2. 성과 표본으로 **판단할 수 있는 범위**와 추가로 필요한 증거는 무엇인가?
3. **보류 상태에서 통보 기한이 도래**하면 누가 어떤 후속 확인을 해야 하는가?

보완 가능 데이터(선택 예시): 계약 원문 발췌·변경 제안서 / 상신·승인·통보·수령확인 이력 / 고정 피·성과 피·캠페인 비용 연결표

## 7. 완료 조건에 대응시키기 (초안)

| 완료 조건 | W02 에서의 후보 |
|---|---|
| 실제로 돌아가는 시스템 | 갱신 통보·기안 접수 → 기한·권한·실질 공헌이익 확인 → 판단(갱신/조건변경/해지 통보 · 기안 승인/부결) → **권한자에게 승인 요청 생성** → 모의 회신 → 계약·기안 **상태 변경** → 바뀐 상태(예: 갱신 확정 시 INF-001 배분 선점)가 **다음 기안 판단에 반영** |
| 세 가지 상황 | ① 정상: 기한 전 상신 → CEO 승인 → 통보 기록 ② 조건 변경: 기한/금액/covenant 구간 변경으로 승인 주체·순서가 바뀜 ③ 정보 부족·거절: 성과 피 조건 없음 / CEO 반려 → 기한 전 재검토 + 후속 확인 작업 생성 |
| 나만의 확장 | 예: 통보 **수령확인 상태**(미확인이면 "통보 완료"로 보지 않고 재통보 작업), 쿠폰 중복 사용 반품률 반영 등 — 미정 |
| 다른 부서 영향 | 재무: covenant 하회 구간과 집행일이 겹치면 승인 주체가 **그룹 CEO**로 바뀜 / 갱신 시 1년 예산 선점 → 다른 인플루언서 기안 재배분 / **SCM · Corevia: 확대 승인 캠페인의 주력 SKU 재고 커버가 부족하면 캠페인 일정 조정 또는 재고 보충 요청 생성(리드타임 12주 · MOQ 제약)** |
| 원본과 가정 구분 | 위 [원본]/[주장]/[집계]/[가정] 태그를 화면·데이터에 그대로 사용 |

> 7절은 설계 출발점이다. 구체 설계를 정하면 별도 문서로 옮긴다.

## 8. 여섯 관점을 W02 에서 보여주는 방법 (초안)

| 관점 | W02 에서 보여줄 것 |
|---|---|
| **온톨로지** (대상 · 관계 · 상태 · 규칙) | **대상**: 인플루언서 · 전속계약 · 캠페인 · 확대 기안 · 주문 · SKU · 채널 · 공급사(Corevia) · 결정권자(마케팅팀/Masil 대표/CEO·이사회) · 승인요청 · 작업. **관계**: 인플루언서–계약(1:1 전속), 계약–기안(하위 집행분), 캠페인–주문–SKU–채널, SKU–공급사. **상태**: 계약(검토중 → 상신 → 승인/반려 → 통보완료 → 수령확인 / 자동갱신), 기안(접수 → 검증 → 상신 → 승인/부결/자동확정). **규칙**: 권한 구간(1천만 · 1억 · 10억), 미통보=체결, 기한 경과=자동확정, covenant 우선 규정 |
| **데이터의 의미와 연결** | 파일별 출처 · 단위(원, VAT 제외) · 스케일(**표본 vs 풀스케일**) · 시점(as-of 2026-06-30/07-01) · 연결 키(campaign_id, sku_id×channel_id, order_id) · 공백(계약 원문 · 성과 피 · 통보 증빙 · 물류/CS 비용 · reserved_qty)과 보완 방법 |
| **분석과 대안 비교** | 인플루언서별 **집행 비중 순위 vs 실질 공헌이익 순위**, 명목 ROAS vs 실질 ROAS, 대안(갱신 / 조건변경 제안 / 해지 통보) × (기안 승인 / 일부 승인 / 부결) 비교 — 결론은 **비중 · 순위 · 방향**까지 |
| **판단을 돕는 화면 (BI)** | 기한 타임라인(7/17 · 8/14 · 9/11 · covenant 구간), 권한 경고(누가 승인해야 하는가), 인플루언서 성과 순위표, SKU 재고 커버 경고, 각 수치의 [원본]/[집계]/[가정]/[주장] 배지 |
| **AI · 사람 · 도구의 역할** | AI: 접수된 통보 · 기안을 읽고 기한 · 권한 · 성과 · 재고를 조회해 **판단안과 근거** 작성. 사람: 권한자가 승인/반려/예외 판단(모의 회신). 도구: 승인요청 생성, 상태 변경, 통보 기록, 발주 제안 생성 |
| **판단 이후의 처리** | 결정 · 회신에 따라 승인요청 · 통보문 · 재검토 작업 · 재고 보충 요청이 **생성 · 갱신**되고 처리 이력이 쌓이며, 바뀐 상태(예: 전속계약 갱신 확정 → INF-001 예산 선점 / 반려 → 기한 전 재검토 작업)가 **다음 기안 판단에 반영** |

기술 · 구조 선택과 그 이유는 설계 단계에서 이 표를 기준으로 정한다.
